**情形 B — 平台不强制，但使用者仍需付出代价（Case B — Optional + User Still Pays）**：
即使作者未开启收费、无收益，只要使用者仍需付出代价（平台默认开启的增值服务、默认勾选的付费项、隐性门槛等）→ 同样视为倒卖；作者若能够关闭却未关闭 → 未经允许的倒卖（0.2），授权自动终止（第 3 条）。

#### 0.1.5 判断原则 / Determining Principle

**一句话：看使用者是否付了代价；只要付了，就是倒卖——平台强制与否、作者有无收益，都不改变定性。**

- **使用者付出任何代价**（钱、币、点、券、积分、代币、虚拟资产、等价物，或任何非现金价值）= **收费提供** → **倒卖**；
- **唯一的"不算倒卖"情形**：使用者**确实无需付出任何代价**即可取得本作品。凡存在付费或等价代价，作者必须主动关闭或另行提供完全免费的获取渠道，否则即视为倒卖。

### 0.2 禁止倒卖 / No Resale

**禁止倒卖**：不得以任何形式**出售、转售、出租、出借、许可、分销牟利**本作品或其**近似复制**，包括但不限于：换名出售、打包售卖、作为付费资源发布、嵌入付费产品等。

#### 0.2.1 「对价」的界定 / What Counts as "Consideration"

**认定"收费提供"时，"对价"包括但不限于以下形式——不以法定货币为限，也不以其是否在某一国家或地区合法流通为前提：**

1. **法定货币及其电子化形式**：人民币、美元、欧元等，以及银行转账、电子支付的等价金额；
2. **在部分国家或地区不被认可、甚至被禁止的货币**：例如**在中国被禁止交易、流通的虚拟货币**（如比特币等）；**无论是否合法、是否可流通，均计入对价**；
3. **电子货币**：电子钱包余额、在线支付账户余额、第三方支付平台内的等价资产等；
4. **代币与充值货币**：平台代币、积分、钻石、金币、点券、礼券、充值余额等；
5. **软货币与硬货币**：仅在特定平台或体系内流通的**软通货**，以及可兑换、可提现的**硬通货**；
6. **游戏内货币**：金币、钻石、点券、绑定点券等，无论是否可提现；
7. **以物易物**：以虚拟道具、账号、资源、服务或其他非货币利益换取本作品。

**核心原则**：不以"是否合法、是否可流通、是否可提现"为准，**而以"使用者是否为获取本作品支付了或转移了任何价值"为准**。

### 0.3 禁止换皮售卖 / No Reskinning

**禁止"换皮"**：不得仅作**表面性、装饰性、微不足道的改动**后即当作自己的作品售卖（含在付费商店、资源市场等发布），**即使保留了署名**。

**认定"换皮"须同时满足以下三项客观标准**（不以作者单方声明为准，争议时提交第三方裁定）：

1. **功能标准 / Functionality**：核心功能、逻辑、结构**未被实质重构**；
2. **改动标准 / Degree of Change**：改动**仅为**表层装饰或**远不足**以构成新作品；
3. **对比标准 / Comparability**：与原作**并排对比**时，**实质相似、难以区分**。

**满足全部三项 → 认定为换皮 → 禁止售卖，视为倒卖。**
**反之（三项中任一项不满足）→ 视为实质性改动 → 可售卖（适用 0.0.1）。**

### 0.4 禁止夹带无用积木 / No Useless Blocks

**禁止**在作品（尤其是署名相关部分）中夹带**空操作积木、弱操作积木、低操作积木**，用以**凑数、规避署名、规避改动幅度要求**或**误导第三方认定**。

- **空操作积木 / Null-operation blocks**：执行后**无任何可见效果或状态变化**的积木（恒返回固定值 / 原值、`true` / `false`、空过程、透传等）；
- **弱操作积木 / Weak-operation blocks**：形式上执行了操作，但**对最终结果无实质影响**的积木（无关紧要的临时变量、重复设置相同值、无贡献的冗余运算等）；
- **低操作积木 / Low-operation blocks**：仅做了**少量操作**、功能**微不足道**、**可被一句话或单个原生积木替代**的积木（简单包装已有功能、封装常量、仅作格式转换等）。

**判断原则**：凡是"新增功能**可被一句话或单个原生积木替代**"的 → 一律视为上述三类之一 → **不计入改动幅度**。

**累计计算**：空操作、弱操作、低操作三类**合并计为一个总量**，不得通过分散在不同位置来规避"改动幅度"要求。

**同时禁止借此稀释或掩盖署名义务**——例如将署名藏进"可被一键关闭的署名积木"，或通过大量无用积木使署名难以被察觉。

### 0.5 禁止隐藏署名页 / No Hiding the Attribution Page

**禁止**通过任何技术手段（密码、输入、隐藏入口、深埋路径、代码混淆、条件跳转等）**隐藏、遮蔽、阻碍**使用者访问署名页或署名信息。

## 1. 署名要求 / Attribution

### 1.1 格式 / Format

署名须采用以下标准格式（顺序、内容不可省略；`<>` 为占位符，实际使用请替换为具体名称）：

```
Powered by <作品名 / Work Name>（<作者名 / Author Name>）
```

- **作品名 / Work Name**：本作品的名称；
- **作者名 / Author Name**：原作者或分发方的署名标识（如 `AKM2498K146`）；
- **多作者 / Multiple authors**：用顿号"、"或","并列，如 `Powered by <作品名>（<作者A>、<作者B>）`。

### 1.2 署名位置与路径深度 / Placement & Path Depth

署名信息须**清晰可见、易于访问**，并满足以下路径深度要求：

#### 1. 1–4 次点击可见 / Visible within 1–4 Clicks

从使用者正常进入的**主界面 / 主菜单**出发，**1 至 4 次点击**内应能访问到署名信息；例如：`主界面 > 菜单 > 设置 > 关于`（4 级，合规）。

#### 2. 页面等级：以"默认菜单"为准，不得超过 3 级 / Page Depth: Default-Menu Path, Max 3 Levels

**默认菜单**：使用者**正常流程中最先 / 最常进入**的主界面、主菜单及其**直接分支**。即 `页面A > 设置 > 关于` 为 3 级，合规。

**非默认菜单不算**：`页面C（非默认）> 页面D > 设置 > 关于` 这类**不在默认菜单内**的路径，即使层级数字 ≤ 4，也**不属于**有效路径，署名无效。

#### 3. 特殊条款（仅限确有必要的作品，如游戏等）/ Special Clause

"主页面 > 暂停页 > 设置 > 关于"这类结构，因作品形态确有必要的，可适用。

**启用条件（须同时满足）：**
- 作品**确实属于**此类特殊结构（主界面 → 暂停页流程）；
- 「关于」页**明确标注"特殊条款 / Special Clause"字样**；
- 整体路径深度**不超过 5–6 级**。

**不满足上述条件 → 特殊条款不生效 → 仍按默认菜单 ≤ 3 级；**
**若实际超过 5–6 级 → 署名过于隐蔽、无效，属违规。**

#### 4. 禁止通过非正常手段隐藏 / No Hiding via Abnormal Means

禁止通过**输入、密码、隐藏入口、代码混淆**等使署名页**不可直接访问**。

### 1.3 不隐蔽 / Not Concealed

署名**不得**：

- **隐藏、模糊、缩小至难以辨认**，或置于**不相关、难以到达**的位置；
- **要求使用者执行额外操作**（输入、解谜、跳转外部链接）才能看到；
- **动态闪烁、滚动过快、仅在特定条件下短暂出现**，导致**实质上无法稳定查看**；
- **以"可被一键关闭 / 一键移除"的方式呈现**署名（含将署名放进可关闭积木、可跳过画面等）；
- **与大量无用积木、装饰元素混杂**，导致署名**难以被察觉**（参见 0.4）。
